# CLAUDE.md — HSynth (tera-synth)

Hybrid synthesizer: platform-independent C++17 engine (`engine/`), desktop host (`desktop/`: Windows and macOS),
Android app (`android/`, Kotlin + Oboe), iOS app (`ios/`, SwiftUI). Docs are in `docs/` (Japanese).

> **Working on a Mac?** Read `docs/HANDOFF_MAC.md` first (handoff from the Windows session; the first task is
> getting the iOS app onto the user's iPhone). Apple build notes: `docs/APPLE.md`.

## Working rules
- Talk to the user in **Japanese**; docs are written in Japanese. Be concise, results first.
- Commit or push only when the user asks; end commit messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

  On a Mac, the macOS host and the iOS app (see `docs/HANDOFF_MAC.md`).
- **Never put the MIDI files or the test sounds into an app bundle** (APK / iOS): they are not to be distributed.
- **Never commit sampled sounds to this repository.** `desktop/data/` (SonicCell / GM recordings, user library) and
  `testdata/` (SoundFonts, Roland instrument definitions, manual-derived lists) are git-ignored test material.
  The sounds live in the private repository **tera-works/tera-synth-assets** (see below); never copy them into this
  repository, a public place, a PR description or an artifact.
- Do not claim something works unless it was built and tested; say what was not verified.

## Build and test
Engine (any OS with CMake + a C++17 compiler; this is what a cloud / Linux session can do):
```bash
cmake -S engine -B engine/build -DCMAKE_BUILD_TYPE=Release
cmake --build engine/build -j
./engine/build/hsynth_tests            # all tests (about 1 min); a name filter can be passed as argument
./engine/build/hsynth_bench 32 2       # CPU cost per layer / effect configuration
```
`engine_golden_render` compares against `engine/tests/golden/`; regenerate only for intended DSP changes
(`HSYNTH_UPDATE_GOLDEN=1`) and say so.

Windows host (Windows only: WinLibs MinGW GCC, Ninja; link `-static`):
```bash
cmake -S desktop -B desktop/build -G Ninja && cmake --build desktop/build
desktop/build/hsynth_desktop.exe --autotest desktop/autotest_out/run   # plays audio, writes report.txt + screenshots
```
Factory presets / demo samples are generated by `engine/build/hsynth_assets android/app/src/main/assets`.

## Test sounds (private assets repository)
`github.com/tera-works/tera-synth-assets` (Git LFS) mirrors the Windows PC's `desktop/data`:
`library/user/gm/` (15 GM test instruments), `library/user/soniccell/` (Roland SonicCell captures, growing while the
capture runs on the PC; `catalog.csv` says what each one is), `presets/user/` ("GM ..." / "SC ..." presets whose
sample paths are relative to `library/`), `soundfonts/MuseScore_General.sf2`. Use it next to this checkout:
```bash
git lfs install
git clone https://github.com/tera-works/tera-synth-assets ../tera-synth-assets   # several hundred MB, growing
./engine/build/hsynth_render --preset "../tera-synth-assets/presets/user/GM Grand Piano.json"     --library ../tera-synth-assets/library --out /tmp/gm_piano.wav
```
Only the Windows PC updates it (`python desktop/tools/sync_assets.py --push`); cloud sessions read it and do not
push to it. If cloning fails (no access), say so instead of working around it.

## Code map
- `engine/include/hsynth/` — `engine.h` (thread contract: `process()` never allocates or locks), `params.h`
  (flat parameter array + metadata; presets store parameters by name), `voice.h`, `dsp/` (oscillators, FM,
  wavetable, SVF, envelopes), `fx/` (effect rack: 31 blocks, convolver, looper).
- `engine/src/params.cpp`, `params_fx.inc` — every parameter's name, range, group (UIs are generated from it).
- `desktop/src/` — ImGui app, WASAPI audio (miniaudio), winmm MIDI; `sampler/` = `hsynth_sampler` auto-sampler.
- Edit text files with an editor tool or Python (UTF-8, LF); PowerShell 5.1 `Set-Content` garbles UTF-8.
